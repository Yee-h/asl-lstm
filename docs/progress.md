## [2026-02-25] E01 多种子集成评估

### 实验目标
通过多种子训练获得多个模型，使用 softmax 概率平均集成提升泛化稳定性。

### 训练配置
- 基线配置: CosineAnnealingWarmRestarts (T0=30, T_mult=2)
- 种子列表: [42, 123, 456, 789, 2024, 4096]
- 每个种子独立训练，保存最佳验证集模型

### 单种子训练结果

| Seed | 验证集最佳 | Epoch | 早停Epoch | 测试集 |
|------|-----------|-------|-----------|--------|
| 42 | 72.70% | - | - | 66.28% |
| 123 | 73.29% | 394 | 544 | 67.05% |
| **456** | **73.59%** | 314 | 464 | **69.38%** ⭐ |
| 789 | 71.81% | 304 | 454 | 65.89% |
| 2024 | 72.70% | 284 | 434 | 68.22% |
| 4096 | 73.29% | 300 | - | 67.44% |

### 分析

**最佳单模型**: seed456
- 验证集: 73.59%
- 测试集: 69.38%

**观察发现**:
1. 种子间测试集波动范围: 65.89% ~ 69.38% (差距 3.49%)
2. 验证集与测试集存在一致性偏差，验证集高不一定测试集高
3. seed456 表现最稳定，验证集和测试集均为最高
4. seed4096 在验证集达到 73.29%（epoch 300），但测试集仅 67.44%，再次印证“验证集高不等于测试集高”

### 分析

**关键发现**:
1. **Softmax 概率平均集成有效提升测试集精度**：最佳单模型 69.38% -> 集成最高 72.09%，提升 +2.71%
2. **最佳组合为3模型集成 (seed123, seed456, seed789)**：达到 72.09%，超过预期的 +0.5~1.5% 增益
3. **并非模型越多越好**：6模型全集成 71.32% < 最佳3模型 72.09%，说明加入低质量模型会稀释集成效果

## [2026-02-27] E02 检查点平均优化

### 实验目标
在验证精度峰值附近的 epoch 窗口选择检查点，进行参数平均（SWA-style），评估是否能提升测试集泛化。

### 实验方法
1. 扫描 seed456 的 92 个 epoch 检查点 (epoch 5~460)
2. 在验证集上评估每个检查点精度
3. 选取验证精度 Top-k (k=3,5,7,10) 的检查点做参数平均
4. 评估平均模型在测试集上的表现

### 关键发现：epoch 检查点 vs EMA best_model

| 模型 | 验证集 | 测试集 |
|------|--------|--------|
| **best_model.pth (EMA)** | **73.59%** | **69.38%** |
| epoch 检查点最高 (epoch 365) | 72.11% | - |

epoch 检查点的验证精度 (max 72.11%) 显著低于 EMA 模型 (73.59%)，
因为 EMA 本身就是一种参数平滑策略。

### 检查点平均结果

| 配置 | 验证集 | 测试集 | 相对 best_model 变化 |
|------|--------|--------|---------------------|
| best_model.pth (EMA) | 73.59% | 69.38% | 基线 |
| Top-3 平均 (epoch 365,420,410) | 71.22% | 67.05% | -2.33% |
| Top-5 平均 | 71.51% | 66.28% | -3.10% |
| Top-7 平均 | 71.51% | 66.28% | -3.10% |
| Top-10 平均 | 71.22% | 66.67% | -2.71% |

### 结论
- **失败** - 检查点平均在本项目中**无增益**
- **根因**: 训练已启用 EMA (decay=0.999)，best_model.pth 本身就是 EMA 平滑后的权重。epoch 检查点是原始(非EMA)权重，其验证精度本就低于 EMA 模型。对原始检查点做参数平均无法超越 EMA 策略
- **教训**: 当训练已使用 EMA 时，检查点平均是冗余操作

### 下一步
- 跳过 E02，标记为"不适用"
- 继续执行 E03（LR Warmup），在 seed456 配置基础上添加学习率预热

## [2026-02-28] E03 LR Warmup 学习率预热

### 实验目标
在训练前期添加线性学习率预热（1e-5 → 8e-4，前5个epoch），缓解训练初期的梯度不稳定问题。

### 配置变更
- `config.py`：新增 `warmup_epochs=5`, `warmup_start_lr=1e-5`
- `train_lstm.py`：前5个epoch使用 `LinearLR`（1e-5→8e-4），之后切换到 `CosineAnnealingWarmRestarts`
- 对比基线：seed456（无warmup）

### 训练结果（seed456_warmup）

| 指标 | 本次（有Warmup） | 对比基线（seed456，无Warmup） |
|------|-----------------|------------------------------|
| 验证集最佳 | 73.59% | 73.59% |
| 最佳验证集 Epoch | 357 | 314 |
| 早停 | ✅ 触发 | ✅ 触发 |
| **测试集** | **65.89%** | **69.38%** |
| 测试集变化 | | **-3.49%** |

### 结论
- **失败** - LR Warmup 显著降低了测试集精度（69.38% → 65.89%，**-3.49%**）
- 验证集指标相同（73.59%），但测试集大幅下降，说明 warmup 导致了更严重的过拟合
- **根因分析**：warmup 阶段改变了调度器的 `last_epoch` 计数起点，导致 `CosineAnnealingWarmRestarts` 的周期性计算产生偏移，破坏了余弦退火的节律；且本项目数据集较小，warmup 带来的额外训练轮次可能加剧过拟合
- **后续处理**：将 `warmup_epochs` 默认值回滚为 0（关闭功能），代码保留供参考

### 已知失败方法更新
- ❌ LR Warmup（导致测试集 -3.49%，调度器周期偏移+小数据集过拟合）

## [2026-02-28] E04 LayerNorm 增强

### 实验目标
在 BiLSTMAttention 模型的 LSTM 输出后添加 LayerNorm，改善训练稳定性并提升泛化能力。

### 配置变更
- `src/config.py`：`ModelConfig` 新增 `use_layer_norm: bool = True`
- `src/model/model_lstm.py`：
  - `BiLSTMAttention.__init__` 新增 `use_layer_norm` 参数
  - 添加 `self.layer_norm = nn.LayerNorm(lstm_output_dim)` 层
  - `forward` 和 `forward_with_attention` 方法在 LSTM unpack 后、attention 前插入 LayerNorm

### 训练结果（seed456_layernorm）

| 指标 | 本次（有LayerNorm） | 对比基线（seed456，无LayerNorm） |
|------|-------------------|--------------------------------|
| 验证集最佳 | **74.78%** | 73.59% |
| 最佳验证集 Epoch | 265 | 314 |
| 早停 Epoch | 415 | 464 |
| **测试集** | **70.16%** | **69.38%** |
| 测试集变化 | | **+0.78%** |

### 结论
- **成功** - LayerNorm 使验证集提升 +1.19%（73.59% → 74.78%），测试集提升 +0.78%（69.38% → 70.16%）
- 模型收敛更快（最佳 epoch 265 vs 314），说明 LayerNorm 改善了训练稳定性
- 测试集增益（+0.78%）低于验证集增益（+1.19%），仍有一定过拟合，但总体有效
- **后续**：LayerNorm 将作为默认配置保留（`use_layer_norm=True`），后续实验在此基础上叠加
