# ASL-LSTM 修复需求文档

## 1. 项目背景

ASL-LSTM 项目用于美国手语识别，覆盖数据预处理、模型训练、模型评估与实时推理。当前代码已具备基础能力，但存在工程一致性不足、配置引用不统一、标签契约混乱、硬编码路径残留、文档与实现偏离等问题，导致可维护性和可复现性下降。

本轮修复目标是基于 `fix.md` 建立强约束、可审计、可回归的修复流程，完成从文档基线到代码重构再到统一验收的闭环。

## 2. 用户角色

### 2.1 算法工程师
- 负责预处理、训练、评估、推理脚本的维护。
- 需要稳定、可复现的训练与推理链路。

### 2.2 项目维护者
- 负责代码结构治理、质量门禁与文档一致性。
- 需要清晰的任务状态、变更记录和验收证据。

### 2.3 自动化 Agent
- 按 `fix.md` 顺序执行任务，不跳步、不并行。
- 每个任务必须完成测试、验证、文档更新。

## 3. 核心流程

1. 读取任务清单并选择唯一进行中的任务。
2. 按任务输入输出修改指定文件。
3. 执行任务验证命令与统一质量门禁。
4. 记录进度日志并推进任务状态。
5. 在全部任务完成后执行最终验收与封版。

## 4. 功能性需求

1. 建立 `docs/` 文档基线，作为单一事实来源。
2. 修复 `transfer_hdf5_data.py` 的配置引用错误。
3. 清除绝对路径和旧项目名硬编码。
4. 统一标签映射契约：
   - `id_to_label`: `{ "0": "book" }`
   - `label_to_id`: `{ "book": 0 }`
5. 抽离 `src/core` 公共模块，集中路径、标签、HDF5 契约逻辑。
6. 对齐 README/API/Architecture 文档与实际代码。
7. 接入 `ruff` 并作为质量门禁。
8. 增加预处理、训练、推理 smoke 测试。
9. 完成全量验证并形成封版记录。

## 5. 非功能性需求

1. 全流程中文化：文档、注释、提交信息、交互输出均为中文。
2. 依赖管理统一使用 `uv`，禁止 `pip/conda`。
3. 每个任务都要执行统一质量门禁：
   - `uv run python -m compileall src`
   - `uv run python -m unittest discover -s src/test -p "test_*.py"`
4. 从 T06 起新增：`uv run ruff check src`。
5. 发生同一任务三次连续失败时，必须停止并记录原因。
6. 分层依赖必须满足：`src/model/*` 与 `src/data_process/*` 仅依赖 `src/core/*`，禁止反向依赖。
